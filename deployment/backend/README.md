# Express backend hosting package

Node 20+ is required; Node 22 is recommended. This must run as an always-on Node service: it handles REST requests, Razorpay webhooks and the persistent order-email worker. It is not a static-host upload or a serverless function bundle.

1. Copy `.env.example` to `.env` for local use, or set the values in your host's private runtime-secret manager. Use the project's Supabase URL, public publishable/anon key, and server-only service-role/secret key. Configure a separately managed SMTP sender and the notification recipient (`sultham456@gmail.com` by default). Without SMTP configuration order creation fails closed; queued jobs are retried after transient delivery failures.
2. Configure Razorpay test-mode Key ID, Key Secret and a separate webhook secret. Point a test webhook at `https://YOUR_API_HOST/api/payments/razorpay/webhook` for `payment.captured` and `order.paid`. Payment remains disabled without all these settings. Live keys additionally require `RAZORPAY_ALLOW_LIVE=true`; enable this only after authorized staging verification.
3. Set `CORS_ALLOWED_ORIGINS` to comma-separated exact HTTPS frontend origins. Set `TRUST_PROXY_HOPS` only if your ingress is trusted and the number of proxy hops is known; never blindly trust forwarded headers. Bind the host's public port to the app's `PORT`, terminate HTTPS, and keep the service running.
4. `npm ci --omit=dev && npm start`. For a container, build from the full repository with `docker build -f deployment/backend/Dockerfile server`, or from this package with `docker build -f Dockerfile .`. Inject secrets at runtime, not in the image or build arguments. `/api/health` confirms process liveness; `/api/config` indicates whether settings are present, not whether providers are reachable.

The service verifies the user's Supabase token, creates order requests and email jobs transactionally, prices from the database, and verifies Razorpay HMAC plus captured status/amount/currency through Razorpay. Payment does not accept a restaurant request. Staff must manually handle refunds if a paid request is rejected and reconcile refund statuses in the database. Never test with live charges or send test emails without permission. See the main repository `README.md` for full deployment, security, monitoring and refund procedures.
